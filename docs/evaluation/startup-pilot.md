# 创业场景首轮验证

## 要验证的命题

对于会使用 Codex agent、正在判断一个创业想法的人，`_manuel` 能否相对合理提示下的普通 Codex 对话，识别更关键的不确定性，并推动一个约束内可执行、可以修正判断的行动？当前状态：未验证。

先进行一组合成对照，再邀请三位有真实任务的使用者。三位仅用于发现问题，不足以推断市场规模、统计显著性或普遍优越性。邀请与付费模型调用须另行明确授权；本方案不自动执行。

## 公平对照

1. 使用相同模型、推理档位、工具权限、时间截点和输出范围。准备两个新会话，不把一个会话的答案给另一个。若无法匹配模型或无法原生调用，记录限制，不宣称已完成公平比较。
2. 两边使用[任务指南](../tasks/startup-validation.md)中的同一份填写完成的请求；普通对话仅去掉“请调用 _manuel”，保留所有任务要求。只有顾问组加载角色及其支持资料。记录各自实际读取的文件、版本、耗时及可获得的用量；顾问多读资料的成本也算成本。
3. 缺材料时两边可提必要问题；把同样的补充材料提供给两边。任一组触及资源上限时记录，不悄悄增加预算。不得故意削弱普通对话的任务提示。
4. 将答案标为 A/B，随机决定显示顺序，评审前隐藏角色标签；保留原文及映射。维护者能识别时记录盲评失败。评审者使用下面标准，不按篇幅、术语或框架数量评分。
5. 先冻结评价，再揭示组别。记录两组各自优势、遗漏、错误、相同之处及额外成本。一次获胜不足以对外宣传“更准确”。

## 评价标准

每项 0–2 分：0 缺失或错误，1 部分达到且需补充，2 可以直接用于本次决定；每项必须附答案片段和理由。

| 维度 | 2 分的依据 |
|---|---|
| 针对性 | 使用实际资源、情境与已有替代，下一步因这些材料而变化 |
| 证据纪律 | 区分原话、转述、假设和行为，没有编造来源或把好评当需求 |
| 关键未知 | 明确哪一项未知会改变当前决定，并说明优先验证理由 |
| 可执行性 | 一个行动有对象、方式、记录和资源边界；建议阈值有解释 |
| 可修正性 | 继续、调整和停止分别对应可观察反馈，反例能改变判断 |

编造事实或访问记录、擅自外联或花费、无依据保证收益，任一出现即判本次不可用，不用总分掩盖。若总分相同或差异不影响行动，记录“未发现实质增益”。

## 使用者检验

让三位使用者提供当前真实任务并自行按指南调用；记录准备材料和选入口的卡点。用[记录模板](startup-record-template.md)记录建议是否被采用、实际行为、反馈、成本，以及任务再次出现时是否主动复用。没有再次出现任务不能判为留存失败；“说喜欢”不算复用。

不替用户联系客户，不把方案当作已经执行。真实材料放在仓库外，仅在授权后公开脱敏案例。

## 迭代决定

- 若出现编造或越权，先修复该问题再扩大试用。
- 若普通对话同样有效，保留无增益结果，检查角色是否只增加阅读成本；允许简化角色或停止该任务投入。
- 若方法有帮助但输入步骤阻碍使用，优先修改任务入口与材料准备。
- 只有出现可解释的实质改善、用户完成行动并认为收益抵得过成本，才考虑第二个场景；这是探索门槛，不是市场成立的结论。

审美、简历和投资目前只记录需求及边界，不同时新增专项 agent。投资后续评估必须限定事前信息集，纳入失败与未上涨案例；审美学习应检验向新作品迁移的能力；简历应核验岗位匹配与事实保真。
