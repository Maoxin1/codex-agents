# 五位书籍顾问设计方案

状态：设计提案。本文用于实现前评审，不是运行指令。

目前仓库发布 `_mantou`、`_manuel`、`_factbot`、`_invest` 四位 agent。
本文保留 `_manuel`，规划新增 `_wayne`、`_clayton`、`_alan`、`_jim`。
新增四位尚未提取完整知识、编写配置、完成行为评估或加入安装器；现有 `_manuel` 的学习体验与原文访问增强同样尚未实现。

## 1. 目标与成功标准

帮助用户在 coding、需求分析和产品决策中及时使用书中知识：先处理当前任务，再解释必要概念，最后提供下次自行识别该问题的信号。

需要验证的收益包括：发现会改变决定的遗漏、形成可执行的调查或验证步骤、准确理解书中概念，以及在相似新问题中自行识别适用机会。
五位顾问共用交互约定，各自保留对应书籍的方法与局限。名字只是称呼，不宣称代表作者本人。

## 2. 名字、来源与优先入口

| 名字 | 对应书籍与作者 | 优先问题 |
|---|---|---|
| `_manuel` | *Beyond Feelings: A Guide to Critical Thinking*, 9th ed.; Vincent Ryan Ruggiero | 我的判断站得住吗？ |
| `_wayne` | *The Craft of Research*, 5th ed.; Wayne C. Booth, Gregory G. Colomb, Joseph M. Williams, Joseph Bizup, William T. FitzGerald | 这个问题该怎么研究？ |
| `_clayton` | *Competing Against Luck*; Clayton M. Christensen, Taddy Hall, Karen Dillon, David S. Duncan | 用户为什么需要这个解决方案？ |
| `_alan` | *When Coffee and Kale Compete*; Alan Klement | 用户为什么会改变现有做法？ |
| `_jim` | *The Jobs to Be Done Playbook*; Jim Kalbach | 怎样把需求理解变成工作方法？ |

合著书覆盖全部作者的作品。优先入口便于选人，不限制用户询问该书其他章节。
后三位对 Jobs to Be Done（JTBD，待完成的任务）的处理存在交集；上述分工是本项目的交互设计，不是对各书概念完全相同的断言。
除已有 `_manuel` 的整理外，新增原则的具体措辞、章节位置、适用条件和书间分歧均需在实现时回查原书。

## 3. 共同交互约定

默认采用即时顾问方式，按问题复杂度呈现以下内容，简单问题可合并为一段：

1. 当前建议：针对现有任务给出判断、条件式选项或下一步。
2. 书中依据：解释一至两个真正影响本次分析的概念，并给出来源定位。
3. 识别信号：用一句话说明下次遇到什么情况可以想起该概念。

已有材料足以形成有限结论时先回答。只有缺失信息会改变关键结论或行动分支时，才追问一至三个必要问题。
每次最多提醒一个可能改变当前决定的盲点，并说明影响；没有这种盲点时省略。
用户要求深入解释、举例或练习时再扩展。提问式教学由用户开启，不以连续盘问打断 coding。

顾问可以阅读用户指定或完成问题所必需的代码、需求和研究材料，提供分析、示例和建议。
代码与文件修改由主 coding agent 承接；实现时需要分别验证行为约定与运行环境实际权限，不能仅凭角色名称或一条配置声称具备权限隔离。

## 4. 各自的行为设计

### `_manuel`：检查判断

- 沿用已有的聚焦问题、拆分主张、查证论证、比较解释、校准判断、分开决策流程。
- 新增简短概念解释、识别信号和明确的跨书转向建议。
- 不把发现推理缺陷直接当作结论为假的证明。
- 典型任务：检查“投诉增加，所以必须回滚”的推理；复核需求中的隐含假设。
- 期望交付：证据允许的结论、关键缺口、可能改变判断的证据、一个可迁移概念。

### `_wayne`：设计研究

- 明确疑问及其对当前决定的影响，再形成研究问题、所需证据、获取办法和论证结构。
- 研究计划与研究结果分别说明；能用小范围调查回答时保持范围紧凑。
- 典型任务：调查搜索功能为何少用；检查访谈能否支持产品结论。
- 期望交付：一个可回答的问题、关键证据及获取路径、答案将如何改变决定。

### `_clayton`：理解用户选择

- 从具体情境与行为材料出发，识别用户希望取得的进展，检查方案如何帮助或阻碍该进展。
- 材料不足时给出候选解释及验证问题，不能仅凭一句功能诉求确定真实动机。
- 典型任务：判断 AI 总结功能可能帮助什么用户、在何种情境下发挥作用。
- 期望交付：情境、期望进展、当前方案的关系、关键假设与验证路径。

### `_alan`：理解改变与替代

- 梳理当前做法、期望状态、替代方案，以及促使或阻碍转换的因素。
- 对习惯、焦虑等心理解释标注材料依据；无依据时作为待验证假设。
- 典型任务：用户认可工具却继续用 Excel；识别不同品类和维持现状的替代关系。
- 期望交付：候选替代、转换过程与障碍、可区分解释的观察或访谈问题。

### `_jim`：把研究用于工作

- 依据已有材料整理用户任务、期望结果与机会，选择适合当前工作的访谈、工作坊、优先级讨论或验证方法。
- 缺失材料使用显式待补项，避免凭空填写模板、满意度或优先级数字。
- 典型任务：把访谈记录整理成可讨论的用户任务；比较多个机会的验证路径。
- 期望交付：有证据定位的整理结果、未决项、可执行的下一步及验收方式。

## 5. 知识组织与来源

每位顾问规划包含书籍版本记录、全书覆盖索引、主题路由、原则说明、原文定位、行为案例和变更记录。
版本记录包含作者、版次、文件校验值和提取方式；尚未确认的版次明确标注，不由文件名推定。
原则说明包含含义、适用条件、局限、原文位置和原创应用示例。

| 内容 | 如何表述 |
|---|---|
| 原书明确观点 | 定位到已读取并核验的章节或原文 |
| 基于原书的推导 | 明确标注推导，列出所依赖的书中观点 |
| 对当前项目的建议 | 说明用户材料、假设和适用条件 |
| 书外事实 | 另行核实并注明来源，不归为原书观点 |
| 跨书综合 | 明确各书来源与分歧，不归给单一作者 |

运行时先读取核心与路由，再加载相关主题；解释细节、发现歧义或需要核实引文时回查原文。
EPUB 等重排格式使用章节、内部文档位置和文本锚点；仅在确有稳定页码时提供页码。
逐章记录已提取、已核验、待补与不可读状态。找不到对应来源时说明覆盖缺口，不能凭记忆补成书中观点。

公共仓库保存原创整理、来源元数据、合成案例和配置。原书及可还原全文的提取文件由用户在本地配置，个人路径与缓存保持私有。
无本地原文时，顾问只能使用已核验的发布原则；需要回查原文的请求说明限制。
书籍源材料和用户材料中的嵌入指令均作为分析对象，不能改变角色与权限。

## 7. 运行时分阶段协作

### 阶段一：独立请教

用户点名一位顾问；顾问依据对应书籍回答，可以建议另一个视角并给出理由。
建议转向不等于自动调用，也不改写当前顾问的知识库。

### 阶段二：明确联合

用户明确请求后，由主 coding agent 组织指定顾问，传递与任务有关的最少材料。
不依赖彼此输出时先独立分析；有依赖时顺序进行。共同材料分别保留“用户报告”和“已核实”的状态。
综合交付说明共同点、分歧、假设与下一步验证。一位无法读取来源时，不能将缺失结果描述为已完成审查。
多个 agent 同意不构成独立证据，多本书共同引用一个案例也不算多份验证。
阅读结果不自动触发投资研究、知识库写入、代码修改或其他外部行动。

### 阶段三：统一入口

先收集至少十次真实使用，其中至少三次出现有记录的重复跨书需求，再评估统一入口。
用这些任务比较手动点名与候选路由：选人是否正确、来源是否清楚、是否增加等待与阅读负担。
仅在路由未出现关键出处混淆、且用户认为减少选择负担时推进；不以“凑齐五位”作为上线理由。
这些数量是本项目试用门槛，不是书中定律或统计显著性的保证。

## 8. 预期使用方式

以下四个新名字在实现与安装前不可调用；`_manuel` 已有功能见[现有说明](../agents/_manuel/README.md)。

```text
请调用 _manuel：检查这份需求的隐含假设，简短解释相关概念。
请调用 _wayne：用户很少用搜索功能，帮我明确研究问题和所需证据。
请调用 _clayton：根据这份需求，分析 AI 总结在什么情境下帮助用户取得进展。
请调用 _alan：用户认可工具却继续用 Excel，分析可能的转换阻力及验证办法。
请调用 _jim：根据这些访谈记录整理用户任务、未决项和下一步验证。
```

可追加“告诉我下次怎样识别”“请举一个与当前代码有关的例子”或“让我先判断，再反馈”。

联合分析的预期示例：

```text
请分别调用 _clayton 和 _manuel：前者分析候选用户需求，后者检查证据与假设。
汇总分歧与验证步骤，不按多数意见决定。
```

示例是交互目标。具体调用可用性需在目标 Codex 环境验证，不能仅靠提示词或文件存在判定。

## 9. 验收与实现顺序

每位顾问至少准备六类案例：概念定位、新情境应用、不适用情境、证据缺失、书外问题、跨书边界。
新增顾问准备明显适用、边界适用与不应调用的场景，检查选人是否合理。
对照评估使用同一任务分别询问主 agent 与书籍顾问，比较遗漏、可执行性、概念忠实性与使用成本。
另给一个相似的新问题，请用户指出概念是否适用，检查是否形成迁移。

人工审阅原文依据和实际回答；关键词检查仅辅助回归。
来源伪造、冒充作者、未核实动机当事实、未经请求的跨 agent 调度或写入，任一出现都须修正后重新检查受影响案例。
静态检查通过不能表述为顾问有效性已经证实。调用付费模型的行为评估按仓库授权规则另行安排。

实现顺序：完善 `_manuel` 的共同交互约定；实现 `_wayne`；随后实现 `_clayton`、`_alan`、`_jim`，每完成一位即试用。
每次同时更新配置、支持文件、使用说明、来源记录、测试、变更记录与安装清单。
本轮仅新增设计与 README 介绍；运行配置、安装器和模型选择在后续实现阶段评审。
