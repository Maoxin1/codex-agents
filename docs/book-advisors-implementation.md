# 三位 JTBD 顾问：设计原因与试用亮点

状态：`_clayton`、`_alan`、`_jim` 已实现试用配置、来源定位、本地原文读取、安装与离线检查资产。模型行为评估仍待运行，不能将设计预期表述为已证实收益。

## 为什么分别保留三位

用户希望在 coding 过程中及时补齐知识，因此入口要能帮助选择视角，同时保留每本书的论述和局限。三位有交集，分工是本项目的使用入口，不是各书只讨论这一件事。

| 顾问 | 首选问题 | 优先交付 | 原书依据与边界 |
|---|---|---|---|
| `_clayton` | 为什么用户会选择这个方案？ | 情境、期望进展、替代和取舍、体验障碍 | C01—C09，涵盖进展、发现、交付与理论限制；不从一句功能要求认定真实动机 |
| `_alan` | 为什么想改变却没改，或采用后退回？ | 状态变化、已有事件、四种力量的证据或未知、区分解释的下一步 | A01—A09，区分选择前与使用中的顾虑和惯性；不用虚构分数或心理诊断填框架 |
| `_jim` | 有了材料，下一步怎样组织工作？ | 一个当前最有用的研究或开发产物、依据、待补项、验证办法 | J01—J10，范围、访谈、任务地图、需求比较、job stories、实验与引导；不默认输出全套模板 |

这些分工经原书回查后细化。例如 Alan 第二版第 16 单元明确讨论 jobs-as-progress 与 jobs-as-activities 的不同解释；Kalbach 的书介绍多种方法，任务地图也明确区别于界面任务和购买旅程。不能把三位简化成同一份 JTBD 提示词，也不能将 Jim 简单贴成“只做活动分析”的标签。

Clayton 书的功能、社会和情绪**维度**不等于所有其他书接受同一套 job **类型**定义。联合输出须保留具体用词和出处，不以多位同意代替独立证据。

## 相比最初“把顾问当作者”的调整

1. **顾问身份与来源可追溯。** 保留单词人名，但不冒充作者；合著书保留全部作者。每条原则连接到原书段落位置，并区分原书观点与本项目应用推导。
2. **有原文入口，也有覆盖边界。** 三位发布 28 条选定原则，原书编号章节或单元均可按需读取。索引与已核验原则分开，缺少原文时诚实收窄答案；不宣称提示词等同于完整原书知识。
3. **针对不同问题给不同产物。** 把“调用谁”连到当前困惑；回答可短可长，概念说明只解释会改变建议的部分，避免打断 coding 的固定教学尾段。
4. **把框架当研究工具。** 心理动机、四力、机会分数、访谈故事均需材料；没有证据就给待验证项与区分方法。结构完整不等于研究已完成。
5. **控制运行时混合。** 设计借鉴彼此的视角；默认运行仍只依据对应书。用户明确要求联合后才比较来源、相同处和分歧，不自动调用全部顾问。

## 来源处理的实际差异

- `_clayton`：本地 EPUB 有第三方修改元数据和附加页面。按正文版权页核对版次与署名，附加页面不作为方法依据；不认证该文件为出版社原始文件。
- `_alan`：标题页明确 Second Edition。原 AZW3 保持完整，读取 EPUB 在本地解包，两者指纹及解包警告有记录。OPF 日期和未核实 ISBN 不冒充已确认出版信息。
- `_jim`：核对 2020 版权页和 ISBN，未写明版次号就不猜测。保留书中其他方法提出者的归属，图示与表格不假装已由文字提取完全验证。

公共读取库减少三份实现漂移，同时按所选章节限制定位，避免单文件多章节 EPUB 读到相邻章节仍引用错误章号。原书、全文提取物与个人路径留在本地，安装会保留各自私有配置。

## 怎样使用

```text
请调用 _clayton：根据这份需求，澄清用户在哪种情境下希望取得什么进展。
请调用 _alan：这些用户认可工具却仍用 Excel，哪些解释有证据，下一步怎样区分？
请调用 _jim：把这些访谈整理成一个当前可用的产物，保留依据、待补项和验证步骤。
```

需要多个视角时明确指定，例如“请分别调用 `_clayton` 和 `_alan`，各按自己的书分析，再说明分歧”。主 coding agent 组织调度，顾问不自动调用彼此；改代码与写笔记仍由主 agent 承接。

## 何时停止优化

先完成来源可信度说明、可执行产物、覆盖边界和原有契约回归，即可试用。后续用实际回答暴露的误判、遗漏、来源混淆或阅读成本驱动修改。
三位各准备九个语义案例，覆盖概念、应用、边界、证据缺失、书外问题、跨书口径、来源失败、嵌入指令与按需原文读取。案例均标记未运行；离线检查通过不证明它们已通过模型行为验收。
无需为完成某个使用次数或规则数量持续扩写；也不因框架多而提前做统一路由。
