# 中文使用手册

这份手册说明如何在 coding 过程中选顾问、提供材料、理解回答，并把建议交给主 coding agent 执行。当前共八位 agent；四位新书籍顾问仍处于试用阶段。

## 1. 安装后，先完成一次简单调用

准备支持自定义 agent 的 Codex 和 PowerShell。使用原书读取工具或运行仓库检查，还需要 Python 3.11 或更新版本。模型和平台要求见[兼容性说明](../COMPATIBILITY.md)。

在仓库根目录的 PowerShell 中执行：

```powershell
./install.ps1
```

随后重启 Codex，在新对话中发送：

```text
请调用 _manuel：新功能上线后，投诉从 5 条变成 10 条。
我认为一定是新界面导致的。请检查这个判断，指出最值得补充的信息。
```

这里的投诉数字是示例。实际使用时换成自己的材料，并说明数字是否已经核实。

如果当前 Codex 不支持原生调用，应明确说明调用限制；普通主 agent 的直接回答不能算作该顾问已经成功运行。

## 2. 先判断需要哪一种帮助

| 当前卡点 | 优先调用 | 希望得到什么 |
|---|---|---|
| 需求表达混乱，不方便交给 coding agent | `_mantou` | 可直接复制使用的提示词 |
| 对自己的判断很确定，但想检查漏洞 | `_manuel` | 关键假设、替代解释和判断边界 |
| 不知道应该研究什么、找什么证据 | `_wayne` | 可研究的问题和最小调查步骤 |
| 用户提出一个功能，却说不清实际用途 | `_clayton` | 具体情境、想取得的进展和现有替代 |
| 用户认可方案，却没有开始或持续使用 | `_alan` | 改变的推动与阻碍，以及区分解释的问题 |
| 已有访谈，但无法形成开发讨论材料 | `_jim` | 合适的研究产物、待补信息和验证步骤 |
| 需要判断一句话、截图或数据是否可靠 | `_factbot` | 有出处的核验、证据状态和不确定性 |
| 需要研究公司或复核长期投资论点 | `_invest` | 先确认范围，再开展研究和论点审计 |

相近顾问的区别：`_manuel` 侧重推理，`_factbot` 侧重外部事实；`_wayne` 侧重研究设计，`_clayton` 侧重用户选择，`_alan` 侧重改变过程，`_jim` 侧重把研究组织成可用产物。

## 3. 提问时，给这四类信息

1. 当前要做的决定，例如“是否值得做一个语义搜索原型”。
2. 已有材料，例如访谈原话、观察记录、日志、代码或需求。
3. 尚未核实的猜测，例如“我怀疑用户找不到入口”。
4. 需要的输出和范围，例如“给三个核查步骤，今天不要改代码”。

通用写法：

```text
请调用 _名字：我正在处理［当前问题］。
已有材料：［事实、原话、记录；注明哪些未核实］。
我的猜测：［暂时的解释］。
请给出［当前需要的产物］，控制在［所需范围］。
```

没有材料也可以先请顾问帮助拟定研究问题；没有调查依据的解释会保留为假设。不要要求它把研究计划包装成已有发现。

## 4. 八个可以直接改写使用的例子

### `_mantou`：优化提示词

```text
请调用 _mantou 优化以下提示词：
我想比较关键词检索与向量检索，目前只有 20 条合成笔记。
先给比较思路，不要改代码，也不要预设我需要向量数据库。
```

它只改写提示词，不执行改写后的任务。成品会显示在回答中，并尝试复制到 Windows 剪贴板；复制失败或工具不可用时，仍保留完整提示词，供手动复制。

### `_manuel`：检查判断

```text
请调用 _manuel：投诉数量在上线后翻倍，我准备立即回滚。
目前不知道同期用户数、投诉渠道和具体内容。
请检查我的因果判断，并说明今晚做决定前最该核查什么。
```

关注它是否区分“证据支持什么”和“现在应该怎样行动”，并说明还有哪些解释。

### `_wayne`：把疑问变成研究

```text
请调用 _wayne：我想加入语义搜索，目前只有两位朋友说“听起来不错”。
请形成一个本周能研究的问题，说明先收集哪一种证据，以及它怎样影响开发决定。
```

### `_clayton`：理解功能背后的用途

```text
请调用 _clayton：用户说“我想要 AI 搜索”。
最近一次事件是会前找资料失败，最后去问同事。
请区分用户提出的方案、实际想完成的事和现有替代，并给一个优先验证的问题。
```

### `_alan`：分析为什么没采用

```text
请调用 _alan：用户试用后说新工具更好，第二天却继续用旧文件夹。
目前只知道他说“旧方法已经习惯了”。
请设计下一次访谈问题，区分不同解释，不要直接替用户认定原因。
```

### `_jim`：整理研究材料

```text
请调用 _jim：甲会前找资料失败后问同事；乙要核对出处却只找到摘要；
丙每天只打开固定三篇笔记。
请整理成开发者能讨论的一页研究草稿，缺失信息留空，给出下一步验证。
```

### `_factbot`：核验宣传或判断

```text
请调用 _factbot 审核这句话：“新检索方式已经证实更准确”。
目前只有开发者报告：选取的 20 个问题中，18 个找到相关笔记，未做对照。
先依据这些材料说明证据支持到哪里，并给出更准确的表述。
```

需要外部核验时，提供原链接、截图、日期和统计口径。它应说明实际查过哪些来源；没有访问外部资料时，相关事实仍未核验。

### `_invest`：先界定研究任务

```text
请调用 _invest：我想复核一家上市公司的长期投资论点，公司稍后确定。
今天先界定研究期限、重点和交付物，复述任务并等我确认，不研究或写入知识库。
```

确认研究范围后才开始正式研究。写入 Obsidian 等文件需要另行确认；指定知识库位置时使用自己的路径，不把私人路径、持仓或案例索引提交到公开仓库。它不执行证券交易。

## 5. 边 coding 边补知识

对五位书籍顾问，可在问题末尾追加其中一句：

- “解释这次最有用的一个概念，再给当前项目的例子。”
- “告诉我下次怎样识别这种问题。”
- “先给当前建议，需要时我再追问原理。”

五位顾问分别依据：

| 顾问 | 书籍 |
|---|---|
| `_manuel` | *Beyond Feelings: A Guide to Critical Thinking*，第九版 |
| `_wayne` | *The Craft of Research*，第五版 |
| `_clayton` | *Competing Against Luck* |
| `_alan` | *When Coffee and Kale Compete*，第二版 |
| `_jim` | *The Jobs to Be Done Playbook* |

名字是称呼，不是作者身份。顾问当前提供选定原则和按需查阅能力，并不等于整本书已经完整整理成知识库。书中方法也不能替代当前市场、用户心理或经营数据的事实核验。

## 6. 需要多个视角时，再明确点名

```text
请主 coding agent 分别调用 _clayton 和 _alan：
前者分析用户期望的进展，后者分析转换障碍。
请基于同一份材料独立回答，再汇总共同点、分歧和下一步验证。
保留各自依据，不按多数意见决定。
```

书籍顾问不会自动召集其他顾问。多位顾问使用同一份访谈，仍然只有同一份上游证据。方法定义不同或结论有分歧时，应保留差异，不能强行统一。

需要实际修改时，再向主 coding agent 说明要采用哪些建议、修改哪些代码或文件。顾问提出的建议本身不扩大执行权限。

## 7. 原书是否必须配置

**日常使用已发布原则，不必先配置全部原书。** 但要问精确引文、尚未覆盖的细节或有歧义的论述，就需要回查匹配的本地原书；无法回查时必须说明限制。

先区分两种文件：

- **支持文件**：随安装提供的 `core.md`、原则索引和主题说明。读取失败时，不能宣称已经按对应资料提供了书籍指导。
- **原书文件**：你自己依法取得的 PDF 或 EPUB，不随仓库分发。不同版本或文件指纹不匹配时，需要重新定位核验。

四位新顾问提供私有 EPUB 配置工具，按各自说明配置即可。`_alan` 使用本地已解包的匹配 EPUB，不直接读取 AZW3，也不会在运行中自动解包。`_manuel` 的原 PDF 核验说明见其指南，不要直接套用其他顾问的 EPUB 命令。

配置入口：[`_manuel`](../agents/_manuel/README.md)、[`_wayne`](../agents/_wayne/README.md)、[`_clayton`](../agents/_clayton/README.md)、[`_alan`](../agents/_alan/README.md)、[`_jim`](../agents/_jim/README.md)。原书路径保留在本机，勿提交原书或私人配置。

## 8. 怎样更新，哪些内容会保留

```powershell
# 预览更新
./install.ps1 -Force -WhatIf

# 更新指定顾问
./install.ps1 -Agent _wayne -Force

# 更新全部
./install.ps1 -Force
```

安装目录由 `CODEX_HOME` 决定；未设置时使用 `$HOME/.codex/agents`。更新后重启 Codex，当前对话不会自动刷新全部配置。

私有的 `source.local.json`、`knowledge-map.local.md` 等非受管文件会保留。你自己改过的受管文件会被更新，包括 agent 的 TOML 模型设置、说明文档和支持代码。更新前备份本地定制，检查[更新记录](../CHANGELOG.md)；模型覆盖的处理方法见[兼容性说明](../COMPATIBILITY.md)。

## 9. 遇到问题时先检查什么

| 现象 | 优先处理 |
|---|---|
| 找不到某位 agent | 检查安装是否成功、安装目录是否对应当前 Codex，再重启；不要把普通回答当作原生调用成功。 |
| 模型不可用 | 查对应 TOML 和当前账号权限，按兼容性说明选择可用模型；安装本身不会授予模型访问权。 |
| 报告支持文件不可读 | 检查对应目录和运行环境。先验证读取通路，无法读取时保留限制，不凭记忆补成原书观点。 |
| 原书指纹不匹配 | 检查文件和版次，按该顾问的来源说明重新核验，避免强行跳过指纹检查。 |
| 剪贴板复制失败 | 从 `_mantou` 的回答中手动复制完整提示词。 |
| `_invest` 一直等确认 | 明确确认或补充研究范围；新增文件写入需要单独授权。 |
| 多位顾问给出不同建议 | 查看各自的问题定义、材料和假设，再决定应补什么证据。 |
| 命令行（CLI）批量评估在 Windows 读不到文件 | 检查已有 Windows 沙箱配置。评估器会先做不消耗模型额度的读取预检；失败时先处理环境，不绕过权限。 |

当前已完成的验证及限制见[首轮评估](evaluation-results-2026-10-27.md)和[读取通路验证](source-access-verification-2026-10-27.md)。日常请教与批量行为评估分开；涉及额外真实模型调用的评估先明确范围与授权。
