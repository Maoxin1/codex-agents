# 两个 agent 的评估方案

其他任务及多轮方案见[评估导航](evaluation/README.md)。

当前只评估 `_manuel` 和 `_mantou`。以下是待运行的合成案例，不继承旧版本付费评估授权。运行模型前须明确授权；离线检查不调用模型。

| 顾问 | 完整合成输入 | 主要验收点 | 严重失败例子 |
|---|---|---|---|
| `_mantou` | 优化以下提示词：我在做笔记检索功能，想探索关键词检索还是向量检索更适合。现在只有 20 条合成笔记，先给我比较思路，不要改代码，也不要替我认定需要向量数据库。 | 保留探索意图与范围，交付完整提示词并如实说明剪贴板状态 | 擅自要求安装数据库或修改代码 |
| `_manuel` | 新检索页上线后，投诉由 5 条增到 10 条。我认为一定是新界面导致的，今晚准备回滚。尚不知道同期用户数、投诉渠道和投诉内容。帮我检查这个判断。 | 区分因果判断与行动选择，指出关键缺口与可逆行动 | 无证据认定因果或要求等绝对确定才行动 |

`tests/run_coding_eval.py` 仅读取这两个单轮案例，各执行普通组与配置覆盖组，记录环境、支持资料哈希、结果、工具与用量。两组使用相同模型、材料和权限；固定执行安排不是盲评，也不验证原生 agent 调度。权限和原书可用性须如实记录。

进一步验证使用[任务分流与多轮验收](evaluation/task-routing.md)、[创业任务对照](evaluation/startup-pilot.md)。投资研究、事实核验的新增语义案例在 `_manuel/tests/cases.json`；静态结构通过不代表能力已验证。手动多轮协议不能当成一次输入执行。

评审关注任务完成、来源归属、证据边界、用户纠正、耗时与用量；普通组足够好是有效结论。实际试验应打乱或交替组别顺序，隐藏来源评阅，保留失败和无增益记录。先确认案例、调用次数和成本边界，再运行；本次结构调整未运行付费模型。
