# 把一个创业想法推进到可验证行动

适合：已经会调用 Codex agent，有一个想法但尚不清楚需求是否存在、目标用户是否会改变行为，或不知道下一步该验证什么的人。使用 `_manuel`，无需新建角色。

本任务不承诺找到成功创业项目。目标是减少无依据的投入，得到一个可以通过实际反馈修正的判断。

## 准备材料

尽量提供以下信息；不知道的直接写“不知道”，不必填完才开始：

- 想服务谁，他们在什么具体情境中遇到什么问题。
- 他们现在用什么办法，为什么可能需要改变。
- 已有证据：访谈原话、实际使用、拒绝、付款或时间投入；标注来源与日期。
- 自己的能力、每周可用时间、可损失预算、能接触的人群。
- 当前决定：探索方向、调查需求、做样品，还是停止投入。
- 以前已经做过的试验及结果，避免重复从零开始。

## 直接调用

```text
请调用 _manuel，帮助我把下面的创业想法推进到下一次验证。
想法与目标用户：［填写］。
用户现在的做法与触发情境：［填写或未知］。
已有材料及其来源：［粘贴获授权的记录，区分原话与转述］。
我的时间、预算、能力和可接触人群：［填写］。
已做过的尝试：［填写或尚未开始］。
本次需要决定：［填写］。
先区分证据与假设，给出当前判断、最关键未知及一项可执行试验，
说明要观察什么、何时继续/调整/停止。数字阈值如由你提出，请说明理由。
若信息不足，提出会改变下一步的必要问题。不要替我联络或购买服务。
```

可追加“解释一个我下次也能用的方法”；赶时间时说“只给今天的一步”。

## 拿到回答后

检查它是否引用了你的具体材料、识别了现有替代、允许假设被推翻，以及行动能否在约束内产生新证据。只有“多访谈、做 MVP、找需求”而没有对象、问题和判断条件，不算任务完成。

实际访谈、制作或联络由你或另行获授权的执行者完成。复盘时带回：做了什么、原始回应、花费、没有完成的原因、哪些证据支持或反驳原假设。顾问的建议不等于你已选定或执行。

参照[合成示例与失败示例](../examples/startup-validation.md)。要判断 agent 是否比普通对话更有用，使用[对照方案](../evaluation/startup-pilot.md)。
