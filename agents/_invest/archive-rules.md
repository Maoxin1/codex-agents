# Obsidian 档案规则

## 1. 目录角色

- 领域入口：`10 日常与领域/投资/投资.md`
- 投资系统：`10 日常与领域/投资/投资系统`
- 原始资料：`30 资料与知识/投资`
- 通用模板：`00 首页与系统/模板`
- 历史聊天：`AI/聊天记录`，只作溯源线索，不作为当前事实来源。

不要新建与现有投资系统平行的第二套根目录，也不要把其它笔记库或代码仓库当成默认知识库。知识库根目录按用户指令、工作区 `AGENTS.md` 或 `INVEST_VAULT_PATH` 解析；无法确定时先询问。

## 2. 读取规则

1. 先读领域入口和与当前任务直接相关的系统入口。
2. 公司已有目录时沿用其结构，不自动改造成统一模板。
3. 先读上一版本、证据账本和决策日志，再提出更新。
4. 历史案例的事实截至日、当时可得信息和事后结果必须分开。
5. PDF、CSV、脚本输出与聊天记录只按其实际证据地位使用。

## 3. 写入确认

研究授权不等于写入授权。写入前输出：

```text
拟修改文件：
修改类型：新建｜追加｜局部更新
变更摘要：
保持不变：
历史是否保留：
潜在影响：
```

获得明确写入确认后，才进行小范围、可审计的修改。

## 4. 保留与版本

- 不删除、移动或重命名既有案例，除非用户单独授权。
- 不覆盖发布前快照、旧估值、旧论点或失败记录。
- 更新时写明 `as_of`、版本、变更原因和下一复核触发器。
- 原始资料与分析笔记分离；引用原始资料时保留路径和发布日期。
- 如果目录结构存在冲突，先报告并提出映射，不擅自整理。

## 5. 新公司最小档案

只有用户确认新建时，才建议以下最小集合；已有公司结构优先：

```text
公司（代码）/
  00 数据与来源.md
  01 投资论点与证据.md
  02 盈利与估值.md
  03 证据账本.md
  04 决策日志.md
```

财报、事件和复核记录按日期追加，不改写历史。

## 6. 轻量测试驱动维护

修改 `_invest` 核心配置时：

1. 先指出要修复的失败行为；
2. 先运行或定义能够复现问题的测试；
3. 只做最小修改；
4. 重跑三个冒烟测试；
5. 记录版本、测试结果和已知局限。

测试只验证流程纪律，不验证未来回报或目标价。
