# `_manuel`：长期思考与行动伙伴

日常不知道该问谁时，从这里开始。简单解释和给定文本草稿直接交付；选择、论证或行动障碍才进入判断流程。个人记录仅在会改变建议时读取，方法资料按具体难点加载。一般提问不自动进入访谈、个人画像或试验。

明确要训练能力时，可以要求“先看我的判断，指出一个关键遗漏，示范修改，再用不同条件的新例子让我练习”。用户未作答前，不声称已经学会；只要结论时不布置练习。

## 使用

已有创业想法时，使用[创业验证任务入口](../../docs/tasks/startup-validation.md)。它按[机会流程](opportunities.md)区分口头好评与行为证据，优先检验会改变决定的一项未知。对照效果尚未验证，示例不是市场需求证明。

仓库根目录运行 `./install.ps1` 默认安装 `_manuel` 和 `_mantou` 两个入口，并提供五本书的方法资料。重启 Codex 后点名调用：

> 请调用 _manuel：我在考虑一个副业方向。先结合我授权的笔记核对目标和约束，等我确认，再直接指出问题，给出首选方案和第一步。

> 请调用 _manuel：只检查这段推理，不需要完整访谈。

> 请调用 _manuel：调研［具体问题］，范围为［地区和时间］。核验关键资料，说明结论的前提、反证条件；也解释一个我可以学会并迁移的方法。

调研和市场分析按[调研流程](research.md)检索、核验和解释。只需结论时可直接说明，不强制教学；联网和数据访问取决于实际运行环境。该流程处于试用阶段，不承诺预测胜率或学习效果。

仓库只提供 `_manuel` 与 `_mantou`。书籍位于 books/，事实核验与投资研究规范位于 tasks/，均作为 `_manuel` 按任务读取的资料，不注册额外角色。旧安装见[迁移说明](../../docs/migration.md)。

## 个人资料与持续使用

知识库按本次路径、工作区 AGENTS.md、MANUEL_VAULT_PATH 依次解析。可在已安装支持目录建立 `context.local.md`，记录用户授权的知识库和聊天导出入口；这个文件不提交 Git，更新时保留。详见 [context.md](context.md)。

ChatGPT、Codex、Gemini 或群聊记录需要实际提供导出或可用连接；本包不会自动获得账号历史。先用少量相关记录验证效果，不以付费导出所有历史为前提。角色只读，不自动维护画像或同步资料；可输出简短复盘，由用户或获授权的主 agent 保存。

接续时优先读取已有的当前状态与一个当前试验，避免重复询问、重新生成计划和维护多份记录。只在行动或判断有变化时更新草稿。历史能力不限定成长上限；质疑既检查准备过多，也检查推进过快和现实约束。

## 五本书与扩充

[方法路由](methods.md)按问题选择已有书籍资料，保留出处、适用范围与分歧。新增逻辑书籍时扩充方法资料与验证用例即可，无需新增 agent。精确引文仍需核验可访问原书。

## 输出与边界

- 直接、有依据地指出矛盾，允许严肃措辞；不辱骂、不诊断人格，不宣称读心。
- 个人记录、推测和用户确认分开；用户纠正后更新理解。
- 机会建议区分适配证据、当代市场证据和待验证假设，不保证收益。
- 本角色提供分析和行动草稿；不执行交易、购买、联络或文件写入。
- 权限由父会话决定；角色约定不等于独立技术沙箱。

## 验证

新增任务分流、约束变化、数字依据和逐轮反馈的[验收流程](../../docs/evaluation/task-routing.md)。旧版单次对照仅用于发现问题，不能证明本次修改已经改善回答或降低用量；本轮仅离线验证。
